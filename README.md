# Release Radar

**Русский** | [English](README.en.md)

Telegram Mini App, который следит за датами выхода кино, сериалов и игр и напоминает о них в день релиза. Весь бэкенд — один Cloudflare Worker и база D1, целиком на бесплатном тарифе.

Бот: [@Your_Release_Radar_Bot](https://t.me/Your_Release_Radar_Bot)

## Что умеет

* **Mini App вместо команд.** Три вкладки — «Скоро выйдет», «Недавно вышло», «Избранное». Фильтры по типу, жанру (10 групп) и стране (9 групп), поиск, карточка тайтла с постерами, актёрами, рейтингами и кадрами. Тема и безопасные зоны берутся из Telegram.
* **Напоминания в чате.** В день выхода — сообщение с постером; через три дня — «посмотрели?»; по понедельникам и субботам — подборка того, что выходит на неделе и на выходных, альбомом постеров.
* **Четыре источника в одной витрине.** TMDB и OMDb для мирового кино, Кинопоиск для российского (в TMDB его почти нет), IGDB для игр. Игры выключены по умолчанию.
* **Рейтинги** IMDb, 🍅 Rotten Tomatoes и Кинопоиска — цветными значками в фирменных цветах.

## Как устроено

```
Telegram ──webhook──►  Worker.fetch()   ──►  D1
                       Worker.scheduled() ──►  D1  ──►  TMDB / OMDb / Кинопоиск / IGDB
Mini App ──/api/*───►  Worker.fetch()   ──►  D1
```

* **Один Worker, две точки входа.** `fetch()` — вебхук Telegram и API мини-аппа, `scheduled()` — четыре расписания Cron Triggers.
* **Витрина собирается заранее.** У Worker жёсткий лимит: 50 подзапросов на вызов. Поэтому списки не собираются на лету — крон раз в полчаса пополняет таблицу-витрину в D1, а приложение читает только её и отвечает без единого внешнего запроса. Класс `Budget` считает подзапросы и останавливает работу до упора в лимит, недоделанное уходит в следующий запуск.
* **Проверка пользователя.** `initData` Telegram проверяется HMAC-SHA256 через WebCrypto на стороне Worker.
* **Без сборки и зависимостей в рантайме.** ES-модули, ванильный JS в мини-аппе, SQL-миграции.

**Стек:** Cloudflare Workers, D1 (SQLite), Cron Triggers, Telegram Bot API и Mini Apps, TMDB, OMDb, Кинопоиск, IGDB (OAuth через Twitch), Wrangler.

## Задачи, которые пришлось решать

* **Дата релиза — не одно число.** У фильма их много: прокат, онлайн, фестиваль, в каждой стране своя. Бот ориентируется на мировую премьеру, иначе фильм, уже неделю идущий в кино, показывался бы как «выходит завтра». Повторный прокат старого кино отсекается, у сериала учитывается сезон, выложенный целиком.
* **Премьеру не отличить по рейтингу.** У сериала, который ещё не вышел, ноль оценок и низкая популярность — он неотличим от самоделки. Признаком заметности стала платформа: премьера на Netflix, Disney+ или HBO проходит без оценок.
* **У игр дата бывает неточной.** IGDB помечает, что известно: день, месяц, квартал или только год. Бот пишет «в 3 квартале 2026» вместо выдуманного числа и показывает даты по платформам, когда они расходятся.
* **Мусор в выдаче.** TMDB ранжирует по мировой популярности, и первые страницы занимают сериалы с ежедневными сериями. Поиск разделён по языкам и неделям, а на витрину тайтл попадает, только если у него есть описание, актёры и хоть какой-то признак интереса.

Подробные инженерные заметки — [docs/notes.md](docs/notes.md).

## Запуск

```bash
npm install
npx wrangler d1 create release_radar          # id вписать в wrangler.toml
npx wrangler d1 execute release_radar --remote --file schema.sql
npx wrangler secret put TELEGRAM_BOT_TOKEN    # и остальные ключи
npx wrangler deploy
```

Ключи: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TMDB_READ_TOKEN`, `OMDB_API_KEY`, `KINOPOISK_API_KEY`, `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET`. Все необязательные, кроме первых трёх: без ключа отключается только свой источник.
