# Release Radar Bot

Telegram-бот, который следит за датами выхода фильмов и сериалов из вашего избранного
и присылает уведомление в день релиза. Плюс еженедельная подборка новинок по вашим жанрам.

Работает целиком на бесплатном тарифе Cloudflare: один Worker (`fetch` + `scheduled`),
база D1, Cron Triggers. Источник данных — TMDB, для эпизодов сериалов резервно TVmaze.

Бот: [@Your_Release_Radar_Bot](https://t.me/Your_Release_Radar_Bot)
Воркер: `https://release-radar-bot.release-radar-bot.workers.dev`

## Два интерфейса

**Mini App** ([src/webapp.js](src/webapp.js)) — всё, что смотрится и нажимается. Открывается кнопкой
«Открыть приложение» в сообщениях бота, кнопкой меню у поля ввода и кнопкой «Открыть» в профиле
(Main App включён в BotFather). Три вкладки:

* **Скоро выйдет** (открывается первой) — релизы на год вперёд (ближние три месяца обновляются каждый час, дальние — по месяцу за час по кругу);
* **Недавно вышло** — последние 7 дней: фильмы в кино и онлайн, премьеры сезонов, сезоны
  целиком;
* **Избранное** — впереди по дням, вышедшее в конце списка, убирается крестиком.

Под вкладками одна строка управления, общая для всех: «Всё / Кино / Сериалы», переключатель
«Все серии» (показывает идущие сериалы, а не только премьеры) и значок 🔍 — по нажатию на месте
фильтров появляется поле поиска.

Тап по строке открывает карточку тайтла: кадр-подложка, постер, даты проката и онлайна,
жанр, длительность, режиссёр, рейтинги, полное описание, актёры с фото, кадры. Один запрос
к TMDB на открытие (`credits,translations,images` одним вызовом).

Страницу отдаёт тот же воркер по `GET /app`, данные ходят через `POST /api/*` из той же D1.
Запросы авторизуются подписью `initData` (HMAC от токена бота, проверка через WebCrypto);
подделка и всё старше суток получают 401.

**Чат** — только уведомления:

| Когда | Что |
| --- | --- |
| понедельник, 09:00 МСК | что из избранного выходит на неделе — альбом постеров и список по дням |
| суббота, 09:00 МСК | что из избранного выходит на выходных |
| день выхода | короткое сообщение с постером: «Обитель зла — премьера в кино сегодня» |
| через три дня | «посмотрели?» с 👍 / 👎 / 🙈 |

`/start` больше не присылает ленту — одно сообщение с кнопкой приложения. Бот не может сам
открыть мини-апп без нажатия: это ограничение Telegram.

Подборки помечают пользователя (`users.week_digest_on` / `weekend_digest_on`), поэтому
4-часовой крон после 9 утра дожимает тех, кому утренний запуск не успел отправить, и никто
не получает подборку дважды. Отдельные напоминания «за три дня» и «за сутки» убраны — их роль
играют подборки. Еженедельная жанровая подборка по пятницам тоже снята: новинки теперь
смотрятся в приложении.

## Что умеет

Главный экран — один пост: альбом из 8 постеров, под ним сообщение с описанием всех восьми
и кнопками.

```
[8 постеров альбомом]

🔥 Ближайшие релизы · 16–25 сентября
фильмы и сериалы

1. 📺 Южный Парк
    сегодня, 16 сентября · премьера 29 сезона · мультфильм, комедия · ⭐ 8.3
    Трей Паркер, Мэтт Стоун · В этом сатирическом сериале, который бесцеремонно…
2. 🎬 Обитель зла
    послезавтра, 18 сентября · фильм · ужасы, триллер
    Остин Абрамс, Зак Черри · Незадачливому курьеру поручено доставить посылку…

[⭐ 1. Южный Парк]
[⭐ 2. Обитель зла]
...
[🎞 Всё][🎬 Кино][📺 Сериалы]
[◀ Назад][стр. 1][Дальше ▶]
```

Что здесь определено ограничениями Telegram:

* **инлайн-кнопки к альбому не поддерживаются** — поэтому кнопки в отдельном сообщении;
* **подпись альбома ограничена 1024 символами**, а обычное сообщение — 4096. Поэтому альбом
  идёт без подписи, а весь текст с описаниями живёт в сообщении под ним;
* **кликабельного действия внутри текста не существует** — в теле сообщения тапается только
  ссылка на URL, поэтому «удалить» не встроить в строку списка, оно живёт кнопкой под ним;
* **состав альбома нельзя отредактировать** (`editMessageMedia` работает только с одиночным
  медиа) — поэтому «Дальше» удаляет прошлый пост и присылает новый, а id сообщений лежат
  в `users.last_post_ids`.

| Экран | Что делает |
| --- | --- |
| 🔥 /trending | Лента ближайших релизов, фильтры кино/сериалы, листалка на три месяца |
| ⭐ /calendar | Восемь ближайших по дням; полный список, архив и удаление — в мини-аппе |
| 🔎 /search | Поиск: терпит опечатки, год в запросе, не ту раскладку и любой язык |
| 🎚 /genres | Жанры для еженедельной подборки |

### Витрина собирается кроном, а не на лету

Первая версия ленты ходила в discover прямо из вебхука и показывала неправду: премьеры сезонов
рассыпаны по десяткам страниц TMDB (в окне 100 дней их около сорока), а дату ближайшей серии
discover вообще не отдаёт — нужен запрос деталей по каждому шоу. За один вебхук столько не успеть,
и в ленту попадали только 7–8 самых популярных. Гангстерленд, Кольца Власти, Южный Парк,
Медленные лошади — всё мимо.

Поэтому [src/catalog.js](src/catalog.js) наполняет таблицу `catalog` кроном раз в два часа:

1. обходит discover (2 страницы фильмов + 3 страницы сериалов) и складывает id;
2. батчем по 30 дотягивает детали — дату, жанры, синопсис, двух актёров, номер сезона;
3. удаляет всё, что уже вышло.

Лента после этого читает готовое из D1 — **ни одного внешнего запроса**, мгновенно.
Сериал попадает в витрину только на премьере сезона (`next_episode_to_air.episode_number === 1`)
и подписывается как «премьера 29 сезона»; все серии по сериалу видно в «Моё ожидание».

#### Порог «известности»

Без отсечки в ленту лезут «Adams Acht», «Nytt på nytt» (55 сезон норвежского ток-шоу) и прочее,
что TMDB считает выходящим, но чего никто не ждёт. Пороги подобраны по данным каталога:

| | Правило | Почему так |
| --- | --- | --- |
| Все | есть описание | тайтл без синопсиса — почти всегда безымянная мелочь |
| Все | текст читаем | арабица и иероглифы в имени актёра или синопсисе — признак ошибочного попадания, а RTL-символы вдобавок переключают направление абзаца и ломают вёрстку поста |
| Все | назван каст | без актёров в карточке остаётся местный эфир вроде «Nytt på nytt» |
| Сериалы | `vote_count >= 100` или `popularity >= 60` | у идущего шоу голоса уже накоплены: Южный Парк 5145, Гангстерленд 843, а Nytt på nytt — 12 |
| Фильмы | есть русское название (`localized`) или `popularity >= 50` | русское название есть только у того, что здесь прокатывают или переводят; нелокализованное инди и видео-премьеры (Adams Acht, Gator Face, Concerto Muerto) отсекаются, громкое без перевода (The Mongoose) остаётся |
| Фильмы | `popularity >= 4` | только чтобы отсечь совсем дно, см. ниже |

Популярность у будущего фильма низкая просто потому, что до выхода далеко: порог `>= 10`
выбрасывал «Джуманджи 3», «Годзиллу» и фильм с Малковичем, а `>= 7` — ещё и Джонни Деппа,
Брэда Питта и «Angry Birds 3». Поэтому основную работу делает заполненность карточки
(описание + читаемый текст + каст), а популярность оставлена символической.

Если русского описания у тайтла нет, берётся английское из `translations` — это приходит
тем же запросом деталей, без лишнего субзапроса.

### Кинопоиск и российское

[src/kinopoisk.js](src/kinopoisk.js) ходит в poiskkino.dev (бывший kinopoisk.dev — старый адрес отвечает
301; официальный API Кинопоиска только для партнёров). Ключ — `KINOPOISK_API_KEY`, бесплатно
200 запросов в сутки. Каталог тратит 1–2 запроса в час на рейтинги КП (один запрос —
пачка до 90 идентификаторов TMDB) и 4 запроса раз в шесть часов на российский каталог.

* **Рейтинг КП** показывается у всех тайтлов, в том числе зарубежных, первым: `КП 8.2 · IMDb 8.3 · 🍅 96%`.
  По горстке голосов (меньше 100) не показывается.
* **Российское берётся из Кинопоиска целиком**, как зарубежное из TMDB: в TMDB нашего кино
  почти нет. Раз в шесть часов четыре запроса списком — фильмы в прокате и онлайн, сериалы
  в эфире и онлайн, окно от недели назад до года вперёд. В ответе уже есть постер,
  описание, актёры, жанры и рейтинг, так что поштучно никуда ходить не надо.
  В базе такие записи хранятся с отрицательным `tmdb_id` (минус id Кинопоиска); карточка,
  избранное и обновление дат для них тоже идут в Кинопоиск. Серий у Кинопоиска нет —
  у сериала известна только премьера. Если тот же тайтл пришёл и из TMDB, запись TMDB
  помечается `dup_of_kp` и в витрину не идёт.
* **Фильтр качества для российского** — «Ждут» на Кинопоиске от 3000 или от 1000 оценок.
* **Перевыпуски** («Сумерки» 2008 года снова в кино) — не новинки: фильм, чья премьера была
  больше чем за 400 дней до релиза, в витрину не попадает.
* **«Без российского»** — настройка пользователя (`users.hide_russian`), ⚙️ в строке фильтров
  приложения. Хранится на сервере, поэтому одинакова на всех устройствах и не сбрасывается.
  Прячет российское из «Скоро выйдет» и «Недавно вышло»; «Избранное» не трогает.

### Фильтры

⚙️ в строке фильтров открывает экран с тремя разделами. Выбор хранится на сервере
(`users.filter_genres`, `users.filter_countries`, `users.show_games`), поэтому одинаков
на всех устройствах. Фильтры действуют на «Скоро выйдет» и «Недавно вышло»; избранное
и уведомления в чате они не трогают.

* **Жанр** — десять кнопок. TMDB называет жанры сериалов иначе, чем у фильмов
  («НФ и Фэнтези» против «фантастики»), а Кинопоиск добавляет свои, поэтому каждый тайтл
  получает набор ключей (`catalog.genre_keys`, см. [src/filters.js](src/filters.js)).
* **Страна** — девять групп (США, Великобритания, Европа, Россия, Корея и Япония, Индия,
  Китай, Турция, Латинская Америка) в `catalog.country_group`.
* **Индийское, китайское, турецкое, корейское, японское** бот собирает по топ‑20 одной страны
  за запуск и помечает `extra = 1`: без явного выбора страны такие тайтлы не видны нигде.
  Иначе они забивают выдачу TMDB — она ранжирует по мировой популярности, а у сериалов
  с ежедневными сериями она высокая.

### Игры

[src/igdb.js](src/igdb.js) — IGDB (база Twitch). Ключи `IGDB_CLIENT_ID` и `IGDB_CLIENT_SECRET`
из консоли разработчика Twitch; по ним раз в два месяца берётся токен, он лежит в
`service_tokens`. Бесплатно, ограничение только по скорости.

* Игры выключены, пока пользователь сам не включит их в фильтрах. Тогда в строке фильтров
  появляется кнопка «Игры».
* Хранятся в том же каталоге с `media_type = 'game'`, `tmdb_id` — это id игры в IGDB.
  Один запрос раз в шесть часов приносит сразу обложку, описание, платформы, студию и оценки.
* **Точность даты.** IGDB помечает, что известно: день, месяц, квартал или только год.
  Если дня нет, бот пишет «в 3 квартале 2026» вместо выдуманного числа (`catalog.date_note`).
* **Платформы** (`catalog.platforms`) идут строкой «Xbox · PC · PS5». В карточке даты по
  платформам показываются, только если они расходятся.
* Оценок до выхода у игр не бывает, поэтому в фильтр качества идёт `hypes` — сколько человек
  добавили игру в список ожидания.

### Рейтинги

**Откуда фильмы.** Фильмы обходятся по датам релиза в России и отдельно в США
(`release_date` + `region`), а не по мировой премьере: иначе фильм, вышедший у нас в прокате
или онлайн позже мира, в «Недавно вышло» не попадал. Для «вышло за неделю» берётся любая дата
релиза, попавшая в неделю.

**Если у TMDB нет IMDb-идентификатора**, рейтинг ищется в OMDb по оригинальному названию и году.
Сезоны антологий TMDB заводит отдельными сериалами («Monster: The Lizzie Borden Story»), а IMDb
знает только всю антологию («Monster») — тогда ищется часть названия до двоеточия.
Не нашли оценку — повтор через сутки (у свежего релиза она появляется в первые дни),
нашли — раз в неделю.

**Почему 🍅 бывает не у всех.** OMDb отдаёт Rotten Tomatoes только для фильмов — у сериалов там
один IMDb (проверено на «Игре престолов»). А у фильма, который ещё не вышел, рецензий нет,
поэтому и Tomatometer пуст: из 26 проверенных будущих фильмов он есть у двух. После
премьеры рецензии появляются, и еженедельная перепроверка каталога (`rated_at`) его подтянет.

TMDB своих внешних рейтингов не отдаёт, поэтому [src/omdb.js](src/omdb.js) ходит в OMDb по `imdb_id`.
Три оценки, которые часто путают, — это три разные вещи:

| | Кто оценивает | Откуда берём |
| --- | --- | --- |
| IMDb 6.2/10 | зрители IMDb (десятки тысяч голосов) | OMDb ✅ |
| 🍅 Tomatometer 46% | кинокритики | OMDb ✅ |
| 🍿 Popcornmeter 39% | зрители Rotten Tomatoes | API не существует ❌ |

IMDb и Popcornmeter — обе зрительские, но это разные аудитории, разные шкалы и разные числа,
подменять одно другим нельзя. Popcornmeter не отдаёт ни один официальный API; на сайте RT он
лежит во встроенном JSON (`audienceScore.score`), но его разбор — это парсинг страницы,
против правил RT и ломается при любом редизайне. Поэтому в боте его нет.

В ленте рейтинг всегда подписан — `IMDb 8.6`, `🍅 95%`, `TMDB 8.4`: голая звёздочка не говорит,
чья это оценка. TMDB показывается только когда оценки OMDb ещё нет (у будущих релизов её обычно
нет вовсе) и только при `vote_count >= 50` — иначе «10.0» по трём голосам вводит в заблуждение.

Крон подтягивает рейтинги порциями по 12 за запуск и только для того, что реально попадает
в витрину: у бесплатного ключа OMDb 1000 запросов в сутки. Данные там бывают подтухшими —
для свежего релиза `imdbRating` может быть `N/A`, хотя на сайте оценка уже есть.

### Прокат и онлайн

У фильма пишется, что именно наступает: «в кино» или «онлайн» (слово «цифра» — жаргон
прокатчиков, в интерфейсе его нет; старые значения в базе нормализует `kindWord`). Если известна
и вторая дата, она идёт следом:

```
Возможная любовь
23 октября · через 36 дней · в кино · онлайн 6 ноября · IMDb 7.7 · 🍅 100%
```

Важная оговорка: дату онлайн-релиза TMDB знает заранее редко — примерно у одного фильма из
двадцати. Обычно она появляется уже после начала проката, и тогда её подхватывает крон дат,
который ходит по избранному каждые четыре часа.

### Что происходит с вышедшим

Ничего не удаляется само — это данные пользователя, и у завершённого сериала может выйти новый
сезон. Вместо удаления:

* основной список показывает только то, что впереди, плюс тайтлы без даты;
* вышедшее уезжает в раздел `📁 Уже вышло` со своей листалкой;
* у сериала со статусом `Ended` / `Canceled` в строке пишется «сериал завершён», чтобы не гадать,
  ждать ли ещё серий;
* крон продолжает проверять такие сериалы, но раз в неделю, а не каждые четыре часа
  (`release_dates.status`). Если объявят новый сезон, `next_episode_to_air` появится, и запись
  сама вернётся в «впереди» — ради этого её и держим.

### Напоминания

Четыре ступени на одно событие — за три дня, за сутки, в день выхода и через три дня
(«посмотрели?» с кнопками 👍 / 👎 / 🙈, ответ пишется в `reactions`):

| | Фильм | Премьера сезона | Обычная серия |
| --- | --- | --- | --- |
| в день выхода (с постером) | ✅ | ✅ | ✅ |
| через 3 дня | ✅ | ✅ | ✅ |

### Что показывается в витринах

* **Язык.** TMDB ранжирует по мировой популярности, и наверх лезут индийские, китайские и
  турецкие релизы. Параметр `with_original_language` принимает только одно значение
  (список через `|` молча игнорируется — проверено), поэтому отсев на своей стороне:
  `KEEP_LANGUAGES` в [src/tmdb.js](src/tmdb.js). Японский и корейский оставлены намеренно.
* **Постер обязателен** — пост строится вокруг постеров.
* **Сериалы ищутся по `air_date`**, а не по `first_air_date`, иначе новый сезон идущего шоу
  никогда бы не попал в ленту. Дату ближайшей серии discover не отдаёт, поэтому по кандидатам
  параллельно тянутся детали.
* **«Вышло за неделю»** — фильмы, вышедшие в кино или онлайн, премьеры сезонов и сезоны,
  выложенные целиком (`recent_*` в каталоге). Сезон целиком определяется по совпадению даты
  сезона с датой его последней серии: у такого релиза нет «следующей серии», и раньше он
  пропадал из ленты в день выхода.
* **«Все серии»** — переключатель в приложении: показывает и идущие сериалы, одной строкой
  с ближайшей серией (`episode_code`). По умолчанию выключен.
* **По умолчанию сериал попадает в ленту только на премьере сезона** (`next_episode_to_air.episode_number === 1`),
  и подписывается как «премьера 24 сезона». Иначе «Симпсоны» и «Закон и порядок» занимали бы
  ленту каждую неделю. Все серии по сериалу видно в «Моё ожидание», когда он добавлен.
* **Мусорные жанры** (новости, ток-шоу, реалити, мыльные оперы) отсечены через `without_genres`.

### Поиск: что делается с плохим запросом

TMDB сам ищет по всем альтернативным названиям, поэтому японский, корейский, ромадзи и транслит
работают без нашей помощи. А вот опечатки, год в запросе и не та раскладка — нет. Поэтому
[src/search.js](src/search.js) идёт по лестнице попыток, пока верхний результат не станет достаточно
похож на запрос (коэффициент Дайса по биграммам ≥ 0.55):

| Приём | Пример |
| --- | --- |
| как есть | `Дюна` → Дюна |
| без года и пунктуации | `Интерстелар 2014` → Интерстеллар |
| другая раскладка | `L.yf` → Дюна |
| без последнего слова | `Властелин колц` → Властелин колец |
| по самому длинному слову | `Гари Поттер` → Гарри Поттер |
| по префиксу | `Дюнна` → Дюна |

Обычно это один субзапрос (совпало сразу), в худшем случае четыре. Найденное всегда
пересортировывается по похожести на запрос, поэтому `Игра прстолов` даёт «Игра Престолов» первой
строкой, а не самый популярный фильм со словом «Игра». Если сработал не исходный запрос,
в шапке честно пишется, по чему нашли.

### Лимит субзапросов

На Workers Free — не более 50 внешних `fetch` за одно выполнение. Поэтому:

* все исходящие запросы идут через `Budget` (`src/budget.js`), лимит 50 минус запас 5;
* `refreshDates()` берёт батч из 30 записей, отсортированных по `last_checked_at ASC`
  (у новых `NULL` — они первыми), и останавливается, когда в бюджете остаётся 10 запросов —
  этот остаток зарезервирован под уведомления;
* крон дат срабатывает каждые 4 часа, так что весь список избранного успевает
  пройти проверку за сутки независимо от размера;
* фильмы, вышедшие больше недели назад, из батча исключаются — их дата уже не изменится;
* TVmaze дёргается только если TMDB не знает следующий эпизод, а сериал не закончен (до 2 запросов).

Расписания в `wrangler.toml`:

```toml
[triggers]
crons = ["17 */4 * * *", "0 6 * * 1", "0 6 * * 6", "37 */2 * * *"]
```

Первое — обновление дат избранного и напоминания, второе (`DIGEST_CRON`) — еженедельная
подборка, третье (`CATALOG_CRON`) — витрина ближайших релизов.
Если в подборочном запуске бюджет кончился и кому-то подборка не ушла, её дошлёт ближайший
четырёхчасовой запуск на остатках бюджета: пользователь получает подборку, если предыдущая
была ≥7 дней назад (`users.digest_sent_at`).

### Как выбирается дата

* **Фильм** — `/movie/{id}?append_to_response=release_dates`. Из регионов RU и US (если их нет —
  из всех) берутся релизы типов Digital / Theatrical / TV. Выбирается ближайшая будущая дата;
  если всё в прошлом — самая ранняя цифровая.
* **Сериал** — `/tv/{id}?append_to_response=external_ids`, поле `next_episode_to_air`.
  Если его нет, но сериал не закончен — запрос в TVmaze по `imdb_id`. Иначе показывается
  будущая премьера или дата последнего вышедшего эпизода.

### Уведомления

Отправляются, когда `release_date` наступила, но не раньше, чем пользователь добавил тайтл
(`release_date >= created_at - 1 день`) — добавление старого фильма не вызывает спама.
Факт отправки пишется в `notifications_log`.

## Отличия схемы от исходного наброска

Три правки, без которых были бы ошибки:

1. `notifications_log`: в первичный ключ добавлены `media_type` и `release_date`.
   Id фильмов и сериалов в TMDB пересекаются (есть и movie 1399, и tv 1399), а для сериала
   уведомление нужно на каждый новый эпизод, а не один раз навсегда.
2. `digest_decisions`: в первичный ключ добавлен `media_type` — по той же причине.
3. `favorites`: добавлен `UNIQUE INDEX (user_id, tmdb_id, media_type)`, чтобы повторное нажатие
   кнопки «добавить» не плодило дубли (`INSERT OR IGNORE`).

Плюс:

* `users.digest_sent_at` — когда пользователю последний раз уходила подборка;
* `notifications_log.stage` в первичном ключе — ступень напоминания (`d3`/`d1`/`d0`/`a3`);
* таблица `reactions` — ответ на «вы посмотрели?».

Для уже развёрнутой базы миграция лежит в `migrations/002_reminder_stages.sql`:

```bash
npx wrangler d1 execute release_radar --remote --file=./migrations/002_reminder_stages.sql
```

## Развёртывание с нуля

```bash
npm install
node scripts/parse-keys.mjs                 # keys.txt -> .dev.vars (+ генерация секрета вебхука)
npx wrangler d1 create release_radar        # database_id вписать в wrangler.toml
npx wrangler d1 execute release_radar --remote --file=./schema.sql
npx wrangler deploy
```

Секреты (значения берутся из `keys.txt`):

```bash
for N in TELEGRAM_BOT_TOKEN TMDB_API_KEY TMDB_READ_TOKEN TELEGRAM_WEBHOOK_SECRET; do
  node scripts/parse-keys.mjs --get "$N" | npx wrangler secret put "$N"
done
```

Регистрация вебхука:

```bash
TG=$(node scripts/parse-keys.mjs --get TELEGRAM_BOT_TOKEN)
WS=$(node scripts/parse-keys.mjs --get TELEGRAM_WEBHOOK_SECRET)
curl -X POST "https://api.telegram.org/bot$TG/setWebhook" -H 'content-type: application/json' \
  -d "{\"url\":\"https://release-radar-bot.release-radar-bot.workers.dev/webhook\",\"secret_token\":\"$WS\",\"allowed_updates\":[\"message\",\"callback_query\"]}"
```

Воркер проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`: чужой POST получает 403.

## Секреты

`keys.txt` и `.dev.vars` лежат в `.gitignore` и не должны попадать в репозиторий.
`scripts/parse-keys.mjs` понимает имена строк из `keys.txt` по маске:
токен бота, `API Key (v3 auth)` → `TMDB_API_KEY`, `API Read Access Token (v4 auth)` → `TMDB_READ_TOKEN`,
`CLOUDFLARE_API_TOKEN`. Секрет вебхука генерируется при первом запуске и переиспользуется из `.dev.vars`.
